Chapter 3: Views and Nesting

Open in VS Code

Two features make Malloy feel different from SQL:

  • Views are named, reusable queries saved inside a source.

  • Nesting puts a whole query inside each row of another query. This lets you answer questions like "what are the top 5 names in each state?" in a single query, with no window functions and no self-joins.

Starting point

We'll use the finished names model from now on. It's in names.malloy, next to this notebook. It has the same year_born, births, decade, and total_births fields you built in Chapter 1, plus a few more.

import "names.malloy"

Running a view

A view is a query that has a name and lives in a source. The model already defines a few. Here's the definition of by_name from names.malloy:

view: by_name is {
  group_by: name
  aggregate: total_births
  limit: 10
}

To run a view, put its name after the arrow, where the curly braces would normally go:

run: names -> by_name

Defining your own views

You can add views to a source with extend, the same way you added dimensions and measures in Chapter 1. Here we create names_plus with two new views:

source: names_plus is names extend {
  view: top_girls is {
    where: gender = 'F'
    group_by: name
    aggregate: total_births
    limit: 5
  }

  view: top_boys is {
    where: gender = 'M'
    group_by: name
    aggregate: total_births
    limit: 5
  }
}
run: names_plus -> top_girls

Nesting: a query inside each row

Here's the big idea of this chapter. Suppose you want the top 5 names in each state. In SQL, this needs a window function (ROW_NUMBER() OVER (PARTITION BY state ...)) and a subquery. In Malloy, you write the inner query inside the outer one with nest:.

run: names -> {
  group_by: state
  aggregate: total_births
  nest: top_names is {
    group_by: name
    aggregate: total_births
    limit: 5
  }

WITH __stage0 AS (
  SELECT
    group_set,
    base."state" as "state__0",
    CASE WHEN group_set=0 THEN
      COALESCE(SUM(base."number"),0)
      END as "total_births__0",
    CASE WHEN group_set=1 THEN
      base."name"
      END as "name__1",
    CASE WHEN group_set=1 THEN
      COALESCE(SUM(base."number"),0)
      END as "total_births__1"
  FROM 'data/usa_names.parquet' as base
  CROSS JOIN (SELECT UNNEST(GENERATE_SERIES(0,1,1)) as group_set  ) as group_set
  GROUP BY 1,2,4
)
, __stage1 AS (
  SELECT
    *,
   CASE WHEN GROUP_SET=1 THEN
                 ROW_NUMBER() OVER (PARTITION BY CAST("state__0" as VARCHAR), group_set ORDER BY  "total_births__1" desc) END  as __row_number__1 
  FROM __stage0
)
, __stage2 AS (
  SELECT * FROM __stage1
   WHERE  NOT ((GROUP_SET = 1 AND __row_number__1 > 5))
)
SELECT
  "state__0" as "state",
  MAX(CASE WHEN group_set=0 THEN "total_births__0" END) as "total_births",
  COALESCE(LIST({
    "name": "name__1", 
    "total_births": "total_births__1"}  ORDER BY  "total_births__1" DESC NULLS LAST) FILTER (WHERE group_set=1),[]) as "top_names"
FROM __stage2
GROUP BY 1
ORDER BY 2 desc NULLS LAST

Each row of the result is a state. Each state row holds its own small table of top names. The nested query only sees the rows for its state. Read it as: "for each state, show total births, and also show the top 5 names within that state."

Notice that total_births means something different at each level. At the outer level, it counts every birth in the state. Inside the nest, it counts the births for one name in that state.

Key takeaways

  • A view is a named query in a source: view: name is { ... }. Run it with run: source -> view_name.

  • Refine a view with + { ... } to add filters, fields, or limits.

  • nest: puts a query inside each row of the outer query. It is the easy way to answer "top N per group."

  • Every level of nesting has its own where:, order_by:, and limit:.
