Chapter 20: Making Data Sing: An Online Store

Open in VS Code

Chapter 19 introduced the five steps of Making Data Sing with the baby-names data:

TYPE the columns → PAIR the types → apply a MOVE → look for a SHAPE → SHARPEN the question

This chapter runs the same five steps on very different data: the online clothing store from Chapter 2 and Chapter 10. Names are about culture. This is about business: sales, customers, products and orders. Watch how the same moves and doors turn up again.

There's a second lesson too. This store's data is simulated: it was generated for demos, not recorded from a real store. Some questions will come back flat, with no pattern at all. Learning to spot a flat answer, and not invent a story for it, is part of making data sing.

  group_by: inventory_items.product_category
  aggregate:
    total_sales
    # percent

WITH __stage0 AS (
  SELECT
    group_set,
    CASE WHEN group_set=1 THEN
      inventory_items_0."product_category"
      END as "product_category__1",
    CASE WHEN group_set=1 THEN
      COALESCE(SUM(base."sale_price"),0)
      END as "total_sales__1",
    (CASE WHEN group_set=1 THEN
      COALESCE(SUM(base."sale_price"),0)
      END)*1.0/MAX((CASE WHEN group_set=0 THEN
      COALESCE(SUM(base."sale_price"),0)
      END)) OVER () as "share_of_sales__1",
    CASE WHEN group_set=1 THEN RANK() OVER(PARTITION BY group_set ORDER BY (CASE WHEN group_set=1 THEN
      COALESCE(SUM(base."sale_price"),0)
      END) DESC ) END as "sales_rank__1"
  FROM 'data/order_items.parquet' as base
   LEFT JOIN 'data/inventory_items.parquet' AS inventory_items_0
    ON inventory_items_0."id"=base."inventory_item_id"
  CROSS JOIN (SELECT UNNEST(GENERATE_SERIES(0,1,1)) as group_set  ) as group_set
  GROUP BY 1,2
)
, __stage1 AS (
  SELECT
    *,
   CASE WHEN GROUP_SET=1 THEN
                 ROW_NUMBER() OVER (PARTITION BY group_set ORDER BY  "total_sales__1" desc) END  as __row_number__1 
  FROM __stage0
)
, __stage2 AS (
  SELECT * FROM __stage1
   WHERE  NOT ((GROUP_SET = 1 AND __row_number__1 > 5))
)
SELECT
  "product_category__1" as "product_category",
  MAX(CASE WHEN group_set=1 THEN "total_sales__1" END) as "total_sales",
  MAX(CASE WHEN group_set=1 THEN "share_of_sales__1" END) as "share_of_sales",
  MAX(CASE WHEN group_set=1 THEN "sales_rank__1" END) as "sales_rank"
FROM __stage2
WHERE group_set NOT IN (0)
GROUP BY 1
ORDER BY 2 desc NULLS LAST
LIMIT 5

Jeans bring in 15.5% of all sales, more than the next category (Accessories, 9.5%) by a wide margin. A share is easier to compare and remember than $1,954,097.

Key takeaways

  • The same five steps work on any dataset. Business data usually has several Whos (customers, products, orders), which opens more doors.

  • Compare like with like. A partial year made growth look like it collapsed. Comparing January–October fixed it.

  • Compared to what? The "October peak" was the store's growth, not a season. Rescaling by the month's total made it disappear.

  • A flat answer is still an answer. Simulated data is often flat. Say so, rather than inventing a story from tiny differences.

  • Event dates on the same row (ordered, shipped, delivered, returned) form an event log. Customer IDs with dates give repeat-purchase analysis.
