Chapter 6: The Malloy Explorer

Open in VS Code

You've been writing Malloy by hand. The Malloy Explorer lets you build the same queries by pointing and clicking on a source's dimensions, measures, and views. Then it shows you the Malloy code it wrote. This is a great way to:

  • get answers fast before you're fluent in the syntax

  • discover what fields a model offers

  • learn the language by reading the code the Explorer generates

In this chapter you'll open the Explorer on the names source, build a few queries, and then read (and run) the Malloy behind them.

📘 Malloy docs. Explorer: visual query builder

Opening the Explorer

  1. In VS Code, open names.malloy from the malloy-textbook-notebooks folder.

  2. Above the line source: names is ... you'll see small links. Click Explore.

You can also open the Command Palette (Cmd+Shift+P / Ctrl+Shift+P), type Malloy: Explore, and pick a source.

A tour of the screen

The Explorer has three panels:

  1. Source panel (left): every dimension, measure, and view in the source. For names you'll see state, gender, year_born, decade, generation ... under Dimensions, total_births, name_count ... under Measures, and by_name, by_state ... under Views.

  2. Query panel (middle): the query you're building, shown as labeled sections (Group By, Aggregate, Filter, Order By, Limit).

  3. Results panel (right): the result, drawn as a table or chart, with tabs that show the generated Malloy and SQL.

💡 Descriptions show up here. Hover over a field in the source panel. Text written with #" above a field in names.malloy (for example #" The decade a baby was born in) appears as its description. This is one reason to document your model. See Chapter 14.

Exercise 1: births by state

Let's build our first query without typing any code.

  1. In the source panel, hover over the dimension state and click Add as group by.

WITH __stage0 AS (
  SELECT
    group_set,
    (FLOOR(base."year"*1.0/10))*10 as "decade__0",
    CASE WHEN group_set=0 THEN
      COALESCE(SUM(base."number"),0)
      END as "total_births__0",
    CASE WHEN group_set=1 THEN
      base."name"
      END as "name__1",
    CASE WHEN group_set=1 THEN
      COALESCE(SUM(base."number"),0)
      END as "total_births__1"
  FROM 'data/usa_names.parquet' as base
  CROSS JOIN (SELECT UNNEST(GENERATE_SERIES(0,1,1)) as group_set  ) as group_set
  GROUP BY 1,2,4
)
, __stage1 AS (
  SELECT
    *,
   CASE WHEN GROUP_SET=1 THEN
                 ROW_NUMBER() OVER (PARTITION BY CAST("decade__0" as VARCHAR), group_set ORDER BY  "total_births__1" desc) END  as __row_number__1 
  FROM __stage0
)
, __stage2 AS (
  SELECT * FROM __stage1
   WHERE  NOT ((GROUP_SET = 1 AND __row_number__1 > 10))
)
SELECT
  "decade__0" as "decade",
  MAX(CASE WHEN group_set=0 THEN "total_births__0" END) as "total_births",
  COALESCE(LIST({
    "name": "name__1", 
    "total_births": "total_births__1"}  ORDER BY  "total_births__1" DESC NULLS LAST) FILTER (WHERE group_set=1),[]) as "by_name"
FROM __stage2
GROUP BY 1
ORDER BY 1 desc NULLS LAST

From the Explorer to your notebook

When you're happy with a query in the Explorer:

  1. Click the Malloy tab in the results panel and copy the code.

  2. In your notebook, add a new Malloy cell and paste it in.

  3. Make sure the notebook has an import "names.malloy" cell above it.

  4. Run the cell, and keep editing by hand if you like.

This back-and-forth is a great way to learn. Build something by clicking, read the code, then change the code by hand and see what happens.

Also check out the SQL tab. It shows the SQL that Malloy generated, which is often much longer than the Malloy that produced it.

Explorer vs. writing code

The Explorer is great for... Writing code is better for...
quick questions and exploring a new model anything you'll keep, share, or reuse
learning which fields exist new dimensions and measures (the Explorer only uses what the model defines)
a first draft of a complicated nest pipelines, calculate:, and other advanced features
people who don't know Malloy yet notebooks with narrative, and anything you'll check into Git

The Explorer only shows what's in the model. If a question needs a new measure, you add it to the .malloy file, and then the Explorer can use it. Good models make the Explorer powerful.

Key takeaways

  • Click Explore above any source: to build queries by pointing and clicking.

  • The Explorer writes ordinary Malloy. Read the Malloy tab to learn the syntax, and copy it into notebooks.

  • The Explorer can only use the dimensions, measures, and views in the model. Better models make better Explorer sessions.
