Chapter 2: Time Truncation

Open in VS Code

Almost every business question has time in it. How are sales trending? Was last quarter better than the one before? Which month is busiest? In this chapter you'll learn how to:

  • truncate timestamps to a year, quarter, month, week, or day with .year, .quarter, .month, .week, and .day

  • extract parts of a date (like "which month of the year") with functions such as month() and day_of_week()

  • build simple trend queries

The baby names data only records a birth year as a plain number, so for this chapter we'll switch to the e-commerce dataset. Its timestamps go down to the second.

Importing a model

In Chapter 1 we defined our source right in the notebook. Usually a source lives in a separate .malloy file (a model) that many notebooks share. You'll learn much more about this in Chapter 5. For now, this one line brings in every source defined in ecommerce.malloy:

import "ecommerce.malloy"

Truncation: rounding time down

To truncate a timestamp is to round it down to the start of a period. created_at.month turns 2021-03-17 14:05:22 into 2021-03, the first moment of that month. Every order from March 2021 lands in the same group.

Here are all the truncations side by side for a few orders:

run: order_items -> {
  limit: 3
  select:
    created_at
    by_year is created_at.year
    by_quarter is created_at.quarter
    by_month is created_at.month
    by_week is created_at.week
    by_day is created_at.day
    by_hour is created_at.hour

   DATE_TRUNC('quarter', base."created_at") as "by_quarter",
   DATE_TRUNC('month', base."created_at") as "by_month",
   (DATE_TRUNC('week', (base."created_at" + INTERVAL '1' DAY)) - INTERVAL '1' DAY) as "by_week",

   DATE_TRUNC('hour', base."created_at") as "by_hour"
FROM 'data/order_items.parquet' as base

A truncation is still a time. It isn't a number or a string. That matters, because Malloy knows how to sort it, display it, and draw it on a chart's time axis.

💡 Weeks start on Sunday. .week truncates to the Sunday at the start of the week.

Extraction: "which month?" instead of "which March?"

Truncation keeps the year: March 2021 and March 2022 are different groups. Sometimes you want to ask "are Marches always busy?" That's seasonality, and it needs the month number (1–12), with the year thrown away. For that, use extraction functions. They return plain numbers:

Function Returns
year(t) the year, e.g. 2021
quarter(t) 1–4
month(t) 1–12
week(t) week of the year, 1–53
day(t) day of the month, 1–31
day_of_week(t) 1 (Sunday) – 7 (Saturday)
day_of_year(t) 1–366
hour(t) 0–23 
run: order_items -> {
  where: created_at.year = @2021
  group_by: month_number is month(created_at)
  aggregate: total_sales
  order_by: month_number
  limit: 12
}

FROM 'data/order_items.parquet' as base

ORDER BY 1 ASC NULLS LAST
LIMIT 12

Did you notice created_at.year = @2021? The @ starts a time literal, a fixed point in time written into your code. @2021 means "the year 2021." You'll see a lot more of this in Chapter 8.

⚠️ Truncation vs. extraction. created_at.month is a time (March 2021). month(created_at) is a number (3). Use truncation for trends over time. Use extraction to compare the same part of different periods (all Marches, all Mondays).

WHERE base."shipped_at" IS NOT NULL
GROUP BY 1
ORDER BY 1 desc NULLS LAST
LIMIT 6

Measuring time between two dates

How long does an order take to ship? Malloy measures the gap between two times with a range, written start to end, inside a function like days(), hours(), or months():

run: order_items -> {
  where: shipped_at is not null
  group_by: order_year is created_at.year
  aggregate: avg_days_to_ship is avg(days(created_at::date to shipped_at))
  order_by: order_year
}

SELECT 
   DATE_TRUNC('year', base."created_at") as "order_year",
   AVG(DATE_SUB('day', CAST(base."created_at" AS DATE), base."shipped_at")) as "avg_days_to_ship"
FROM 'data/order_items.parquet' as base
WHERE base."shipped_at" IS NOT NULL
GROUP BY 1
ORDER BY 1 ASC NULLS LAST

created_at::date casts the timestamp to a date so both ends of the range have the same type.

What about the names data?

In the names dataset, year_born is a plain number like 1987, not a timestamp. So .month and .quarter make no sense for it. The decade dimension from Chapter 1, floor(year_born / 10) * 10, is the integer version of "truncation": it rounds a year down to the start of its decade.

import "names.malloy"
run: names -> {
  where: name = 'Jennifer'
  group_by: decade
  aggregate: total_births
  order_by: decade

Key takeaways

  • .year, .quarter, .month, .week, .day, .hour, and .minute truncate a time to the start of a period. The result is still a time.

  • Group by a truncated time to build a trend. Malloy sorts time groups newest-first unless you order_by: them.

  • Extraction functions (month(), day_of_week(), ...) return numbers and are good for seasonality.

  • days(a to b) measures the time between two dates.
