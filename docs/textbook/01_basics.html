Chapter 1: The Basics

Open in VS Code

In this chapter you'll write your first Malloy queries. By the end you will know how to:

  • point Malloy at a data file with a source

  • run a query with run:

  • summarize data with group_by: and aggregate:

  • narrow results with where:, sort with order_by:, and cut them off with limit:

  • save reusable logic in a source as dimensions and measures with extend

We'll use the U.S. baby names dataset for the whole chapter. Each row says something like "In 1987, 312 girls born in Ohio were named Jessica."

Your first source

Malloy queries always start from a source. A source is a table of data plus any extra fields you choose to define on it. The simplest source is a file on disk. This cell tells Malloy: "there is a source called names_raw, and it is the Parquet file data/usa_names.parquet, read with DuckDB."

source: names_raw is duckdb.table('data/usa_names.parquet')

Nothing ran yet. We only defined something. The duckdb part names the connection (the database engine that will do the work). DuckDB runs right on your laptop, and it's built into the Malloy VS Code extension.

📘 Malloy docs. Sources · Connections

Your first query

A query has three parts: run:, a source, an arrow ->, and then a set of curly braces { } that say what you want. Let's count the rows.

run: names_raw -> {
  aggregate: row_count is count()
}
QUERY RESULTS 
[
  {
    "row_count": 6311504
  }
]
SELECT 
   COUNT(1) as "row_count"
FROM 'data/usa_names.parquet' as base

About 6.3 million rows. Read the query out loud: "Run against names_raw, and aggregate a field called row_count, which is count()."

The pattern new_name is expression shows up all over Malloy. The name always comes first.

group_by and aggregate

Most analysis is "split the data into groups, then summarize each group." In Malloy, group_by: makes the groups and aggregate: summarizes them. How many babies were born in each state?

run: names_raw -> {
  group_by: state
  aggregate: total_births is `number`.sum()
}
QUERY RESULTS

    "total_births": "24186112"

    "state": "PA",
    "total_births": "17533809"

    "state": "IL",

    "total_births": "15075504"

SELECT 
   base."state" as "state",
   COALESCE(SUM(base."number"),0) as "total_births"
FROM 'data/usa_names.parquet' as base
GROUP BY 1
ORDER BY 2 desc NULLS LAST

A few things to notice:

  • `number`.sum() adds up the number column. Malloy writes aggregates with a dot (column.sum(), column.avg(), column.max()). You can also write them the SQL way: sum(column).

  • The results come back sorted by the aggregate, largest first. When you don't say how to sort, Malloy picks a sensible order for you.

  • There was no GROUP BY 1 and no list of columns to repeat. Malloy writes that SQL for you. Click the SQL button above the result to see it.

You can group by more than one thing and aggregate more than one thing:

run: names_raw -> {
  group_by: gender
  aggregate:
    total_births is `number`.sum()
    distinct_names is count(name)
    rows is count()
}
QUERY RESULTS 
[
  {
    "gender": "M",
    "total_births": "166219447",
    "distinct_names": 14180,
    "rows": 2801180
  },
  {
    "gender": "F",
    "total_births": "153512251",
    "distinct_names": 21375,
    "rows": 3510324
  }
]
SELECT 
   base."gender" as "gender",
   COALESCE(SUM(base."number"),0) as "total_births",
   count(distinct base."name") as "distinct_names",
   COUNT(1) as "rows"
FROM 'data/usa_names.parquet' as base
GROUP BY 1
ORDER BY 2 desc NULLS LAST

count(name) counts distinct values of name. Plain count() counts rows.

Extending a source with dimensions and measures

The real power of Malloy is that you can save logic in the source so every query can reuse it. You do that with extend { }. Inside, you can add:

  • dimensions: values calculated for each row (things you group by or filter on)

  • measures: values calculated across many rows (things you aggregate)

  • renames: friendlier names for raw columns

Let's build a better names source on top of names_raw.

source: names is names_raw extend {
  rename: year_born is `year`
  rename: births is `number`

  dimension:
    decade is floor(year_born / 10) * 10
    name_length is length(name)

  measure:
    total_births is births.sum()
    name_count is count(name)
}

Putting it together

Key takeaways

  • A source is data plus fields you define on it. duckdb.table('file.parquet') makes a source from a file.

  • run: source -> { ... } runs a query.

  • group_by: makes groups, aggregate: summarizes them, and where: filters rows first.

  • order_by: and limit: control sorting and size. Malloy picks a sensible sort when you don't.

  • extend { } adds dimensions (per row) and measures (across rows), so logic lives in one place.
