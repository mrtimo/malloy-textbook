Chapter 11: Percent of Total

Open in VS Code

"What share of the total is this?" is one of the most common questions in analysis. What percent of babies were named Olivia? What share of sales came from Jeans? Which category drove this year's growth? In SQL, these questions need subqueries or window functions. In Malloy, they take two functions:

  • all(measure): compute a measure while ignoring the query's grouping

  • exclude(measure, dimension): compute a measure while ignoring specific grouping dimensions

You'll use them for share, contribution, and index calculations.

import "names.malloy"
import "ecommerce.malloy"

all(): the grand total

all(total_births) is total births across all the rows the query sees, ignoring group_by:. Put it next to the regular measure and the idea is obvious:

run: names -> {
  where: year_born = 2021
  group_by: gender
  aggregate:
    total_births
    everyone is all(total_births)
}
QUERY RESULTS 
[
  {
    "gender": "M",
    "total_births": "1492780",
    "everyone": "2812875"
  },
  {
    "gender": "F",
    "total_births": "1320095",
    "everyone": "2812875"
  }
]
WITH __stage0 AS (
  SELECT
    group_set,
    CASE WHEN group_set=1 THEN
      base."gender"
      END as "gender__1",
    CASE WHEN group_set=1 THEN
      COALESCE(SUM(base."number"),0)
      END as "total_births__1",
    MAX((CASE WHEN group_set=0 THEN
      COALESCE(SUM(base."number"),0)
      END)) OVER () as "everyone__1"
  FROM 'data/usa_names.parquet' as base
  CROSS JOIN (SELECT UNNEST(GENERATE_SERIES(0,1,1)) as group_set  ) as group_set
  WHERE base."year"=2021
  GROUP BY 1,2
)
SELECT
  "gender__1" as "gender",
  MAX(CASE WHEN group_set=1 THEN "total_births__1" END) as "total_births",
  MAX(CASE WHEN group_set=1 THEN "everyone__1" END) as "everyone"
FROM __stage0
WHERE group_set NOT IN (0)
GROUP BY 1
ORDER BY 2 desc NULLS LAST

Each row has its own total_births, and the same everyone total. Notice that all() still respects where:. "Everyone" means everyone born in 2021, because those are the only rows the query sees.

Share: percent of total

Divide by all(...) to get a share. Add # percent to format it:

run: names -> {
  where: year_born = 2021
  group_by: state
  aggregate:
    total_births
    # percent
    share_of_us is total_births / all(total_births)
  limit: 10
}

Remember the births_per_100k measure in names.malloy? Now you can read its definition:

births_per_100k is floor(total_births / all(total_births) * 100000)

It's just a share, scaled up so it's easier to read.

all() with dimensions: share within a group

Give all() one or more dimension names, and it keeps grouping by those dimensions, ignoring the rest. With two group_by: fields, this gives "share within each group":

run: names -> {
  where: year_born = 2021, gender = 'F'
  group_by: state, name
  aggregate:
    total_births
    state_total is all(total_births, state)
    # percent
    share_of_state is total_births / all(total_births, state)
  having: state = 'VT' | 'HI'
  order_by: share_of_state desc
  limit: 10
}

exclude(): ungroup specific dimensions

exclude(measure, dim) is the mirror image of all(measure, dim): instead of listing the dimensions to keep, you list the ones to drop. With group_by: state, name, these two are the same:

keep state, drop name
all(total_births, state) lists what to keep
exclude(total_births, name) lists what to drop

Here's the proof, with both forms side by side:

run: names -> {
  where: year_born = 2021, gender = 'F'
  group_by: state, name
  aggregate:
    total_births
    keep_state is all(total_births, state)
    drop_name is exclude(total_births, name)
    keep_name is all(total_births, name)
    drop_state is exclude(total_births, state)
  limit: 5
}

Shares inside a nest

In a nested query, all(measure) is the total for the parent row. That makes "share within each group" easy to read:

run: names -> {
  where: year_born = 2021, gender = 'F'
  group_by: state
  aggregate:
    total_births
    # percent
    share_of_us is total_births / all(total_births)
  nest: top_names is {
    group_by: name
    aggregate:
      total_births
      # percent
      share_of_state is total_births / all(total_births)
    limit: 3
  }
  limit: 5
}

⚠️ Check nested exclude() results. The Malloy docs say exclude() inside a nest may name a dimension from the outer query (for example, exclude(total_births, state) in a nest under group_by: state). In the Malloy version used to build this book, that pattern sometimes returned the wrong number (the same value for every state). Until you've checked it, prefer flat queries with all(m, dim) for these comparisons, as in the index example below, and compare a few values against a query you trust.

Contribution: who drove the change?

Contribution answers "how much of the change came from each group?" It's a share of a difference. Sales grew from 2020 to 2021, and each category contributed part of that growth:

run: order_items -> {
  extend: {
    measure:
      sales_2020 is total_sales { where: created_at ~ f'2020' }
      sales_2021 is total_sales { where: created_at ~ f'2021' }
  }
  group_by: inventory_items.product_category
  aggregate:
    sales_2020
    sales_2021
    # currency
    growth is sales_2021 - sales_2020
    # percent
    share_of_2021_sales is sales_2021 / all(sales_2021)
    # percent
    contribution_to_growth is (sales_2021 - sales_2020) / all(sales_2021 - sales_2020)
  order_by: contribution_to_growth desc
  limit: 10
}

Index: over- or under-represented?

An index compares a share in one group with the same share overall. 100 means "typical." 200 means "twice as common here as everywhere else." 50 means "half as common."

index = (share of the name within this state) ÷ (share of the name nationally) × 100

Which girls' names are most distinctively associated with a state? We need four ingredients, and all() provides them all:

run: names -> {
  where: year_born ~ f'[2010 to 2021]', gender = 'F'
  group_by: state, name
  aggregate:
    total_births
    # percent
    state_share is total_births / all(total_births, state)
    # percent
    national_share is all(total_births, name) / all(total_births)

  limit: 15
}

💡 Why not where: state = 'UT'? A where: removes every other state's rows before anything is computed, so "national share" would quietly become "Utah share" and every index would be 100. When you compare a part with the whole, make sure the whole is still in the query.

Key takeaways

  • all(m) computes measure m over every row the query sees, ignoring group_by: (but respecting where:, and before limit:).

  • all(m, dim) keeps grouping by dim. exclude(m, dim) drops dim. Both give "share within a group."

  • In a nest, all(m) is the parent row's total.

  • Share = part ÷ all(part). Contribution = change ÷ all(change). Index = local share ÷ overall share × 100.

  • To compare a part with the whole, keep the whole in the query. Use filtered measures, such as m { where: state = 'UT' }, for the part, instead of a where: that throws the whole away.
