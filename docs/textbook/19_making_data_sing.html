Chapter 19: Making Data Sing

Open in VS Code

You know how to write Malloy. This chapter is about what to ask.

Handed a new dataset, most people group by a column, sum a number, sort, and stop. "The most common boys' name is James." That's true, but nobody leans forward. Better questions come from noticing what kinds of columns a dataset has and which ones appear together.

Making Data Sing is a five-step framework for doing that:

TYPE the columns → PAIR the types → apply a MOVE → look for a SHAPE → SHARPEN the question

This chapter explains each step and works through it on the baby-names data. Chapter 20 applies the same steps to an online store, so you can see the framework work on a very different kind of data.

📄 Handout and slides. A one-page version of the framework, with pictures, is at making-data-sing.pages.dev. You can also download the one-page handout (.docx).

Before you start: picking a dataset that can sing

The framework works on any data, but some datasets give you far more to work with. Use these tips when you choose data for a project.

1. Count the column types. Look for at least four of the five types (Step 1 below explains them): a Who/What, a Kind, a When, a Where and a How much. Each type you have adds new pairs, and each pair asks its own questions.

2. Look for a "Who" with many values. A column with hundreds or thousands of distinct things (names, products, songs, players, companies) gives you the richest questions: which ones rise, fall, peak, cross over or stand out.

3. Look for a long "When". Many years, or many months, let you ask about change, peaks, fads and trends. A dataset with one year, or no dates at all, can't answer any When question.

4. Prefer one row per event. Raw data, with one row per sale, game, trip, arrest or visit, can be summarized any way you like. Data that someone has already summarized (one row per country with a total) has lost most of its questions.

5. Knock on the three doors (Step 4 below) before you commit:

Door Look for Example
➡️ Order an ID that appears in many rows, plus a date a customer with many orders, a patient with many visits
🔗 Pair rows that share a key items in the same order, songs on the same playlist
🪆 Nest a category inside another category city → state → region, product → category → department

6. Choose real data over simulated data. Simulated "demo" data is often generated at random, so its patterns are flat. You'll see this in Chapter 20.

7. Size and documentation. A few thousand to a few million rows is ideal. Most important, make sure you can say what one row means.

A quick scorecard:

Dataset Who Kind When Where How much Doors
Baby names (this chapter) name sex year, 1910–2021 state births Order, Pair, Nest
Online store (Chapter 20) customer, product, brand category, status, traffic source order date, ship date country price, cost Order, Pair, Nest
ICE arrests (Chapter 16) country of citizenship, person arrest method, criminality arrest date state, ICE office age, days to departure Order, Pair, Nest
GDP by country and year country — year country GDP Order only

The last row is a typical "summary" table: one number per country per year. You can ask about growth, but there's no Who beyond the country, no Kind and only one door.

The two-minute test. Load the data and look at ten rows. If you can write three questions from three different pairs in five minutes, it's a keeper.

The framework at a glance

1. TYPE: name each column's job

Type Plain-English question Examples
👤 Who / What (entity) Which thing? name, product, student
🏷️ Kind (category) What group? sex, department, region
🕒 When (time) When? year, date, term
📍 Where (place) Where? state, country, zip code
🔢 How much (measure) How many? count, price, minutes

2. PAIR: every pair of types asks its own question

Pair Signature question
Who × When When did it peak? Is it a fad or a classic?
Who × Kind Which ones crossed over from one group to another?
Who × Where Where is it unusually popular?
Kind × When Is the gap between groups growing or shrinking?
Where × When Are places becoming more alike or more different?
How much × anything How concentrated is the total?

3. MOVE: turn a flat answer into a story

Family Moves Why
⚖️ Rescale (make it fair) count → share, count → rank Totals differ; shares and ranks compare fairly
↔️ Contrast (compare it) change, over-index, top-N within each group Finds movers and what's distinctive, not just what's big
🔦 Spotlight (find the story) peak / first / last, concentration, reversals, the identifier is data Gives the number a timeline, a twist or a hidden pattern

4. SHAPE (advanced): three doors

Door Ask What it unlocks Malloy tool
➡️ Order Can I put rows in order within one entity? sequences, cohorts, repeat behavior, rank over time calculate: with rank(), lag(), row_number() (Chapter 12)
🔗 Pair Can I pair rows that share a key? baskets, networks, things that go together a pipeline or a self-join (Chapter 10)
🪆 Nest Does one category sit inside another? drill-down, hierarchies join_one: to a parent table, then nest: (Chapter 3)

5. SHARPEN: turn a seed into a full question

A seed is a few words ("names over time"). A full question has five parts: the subject, the measure, the move or shape, the comparison, and the surprise: what result would surprise you? Write your guess down before you run the query.

Test: could two classmates compute the same answer from your question? If not, it's still a seed.

All five types: this dataset can sing. The model in names.malloy also adds decade, name_length and first_letter. Notice that first_letter turns the Who itself into data. That's one of the Spotlight moves.

WITH __stage0 AS (
  SELECT
    group_set,
    CASE WHEN group_set IN (2,1) THEN
      base."year"
      END as "year_born__2",
    CASE WHEN group_set=2 THEN
      base."name"
      END as "name__2",
    (CASE WHEN group_set=2 THEN
      COALESCE(SUM(base."number"),0)
      END)*1.0/MAX((CASE WHEN group_set=1 THEN
      COALESCE(SUM(base."number"),0)
      END)) OVER (PARTITION BY CASE WHEN group_set IN (2,1) THEN
      base."year"
      END) as "share__2"
  FROM 'data/usa_names.parquet' as base
  CROSS JOIN (SELECT UNNEST(GENERATE_SERIES(0,2,1)) as group_set  ) as group_set
  WHERE base."gender"='F'
  GROUP BY 1,2,3
)
, __stage1 AS (
  SELECT
    "year_born__2" as "year_born",
    "name__2" as "name",
    MAX(CASE WHEN group_set=2 THEN "share__2" END) as "share"
  FROM __stage0
  WHERE group_set NOT IN (0,1)
  GROUP BY 1,2
)
SELECT 
   base."year_born" as "year_born",
   base."name" as "name",
   COALESCE(SUM(base."share"),0) as "share_of_girls"
FROM __stage1 as base
WHERE base."name" IN ('Jennifer','Elizabeth')
GROUP BY 1,2
ORDER BY 1 ASC NULLS LAST

Jennifer is a fad. It rose from almost nothing to a peak in 1974, when nearly 5% of girls got the name, and then fell back to 0.05% by 2021. Elizabeth is a classic: it has stayed between about 0.5% and 1.7% for over a century.

The move here is share (a Rescale move). Raw counts would mislead: far more babies were born in the 1950s baby boom than in the 1930s, so every name looks bigger then. Share takes that out.

The pipeline matters too. Stage 1 computes each name's share out of all girls. Stage 2 keeps the two names. If you filtered to Jennifer and Elizabeth first, all() would only see those two names.

Who × Where: where is a name unusually popular?

The most common names in Utah look like everywhere else. The most distinctive ones don't. To find them, compare each name's share in Utah to its share in the whole country. That ratio is an over-index (a Contrast move): 3.0 means "three times as popular in Utah as nationally."

run: names -> {
  where: gender = 'F' and decade = 2010
  group_by: name
  aggregate:
    utah_births is total_births { where: state = 'UT' }
    utah_share is total_births { where: state = 'UT' } / all(total_births { where: state = 'UT' })
    us_share is total_births / all(total_births)
} -> {
  where: utah_births >= 500
  select: name, utah_births
    # number="0.0"
    over_index is utah_share / us_share
  order_by: over_index desc
  limit: 10
}

Full question: Which names given to at least 2,000 babies in the 2010s came closest to 50% girls, and what percent girls were they in the 1980s?

run: names -> {
  where: decade = 1980 | 2010
  group_by: name
  aggregate:
    births_2010s is total_births { where: decade = 2010 }
    # percent
    pct_girls_2010s is total_births { where: decade = 2010 and gender = 'F' } / total_births { where: decade = 2010 }
    # percent
    pct_girls_1980s is total_births { where: decade = 1980 and gender = 'F' } / total_births { where: decade = 1980 }
} -> {
  where: births_2010s >= 2000
  select: name, births_2010s, pct_girls_2010s, pct_girls_1980s
    distance_from_even is abs(pct_girls_2010s - 0.5)
  order_by: distance_from_even
  limit: 10
}

Checklist for your own data

  1. ☐ Type every column: Who, Kind, When, Where, How much.

  2. ☐ Pair types: pick two pairs and write their signature questions.

  3. ☐ Move: apply moves from at least two different families.

  4. ☐ Shape: knock on all three doors. Order? Pair? Nest?

  5. ☐ Sharpen three seeds into full questions, and write your expected answer first.

Key takeaways

  • The questions a dataset can answer depend on which types of columns it has and which appear together.

  • Pairs of types give you ready-made questions: Who × When asks about peaks and fads, Who × Where about over-indexing, Kind × When about gaps.

  • Moves turn flat answers into stories: rescale (share, rank), contrast (change, over-index, top-N within groups), spotlight (peaks, reversals, concentration, the identifier as data).

  • The three doors (Order, Pair, Nest) open when rows relate to each other. In Malloy they usually mean a window function, a pipeline or join, or a nest.

  • A full question names the subject, measure, move, comparison and expected answer. The gap between what you expected and what you found is where insight lives.
