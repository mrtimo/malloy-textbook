Chapter 8: Filtering and Time Comparisons

Open in VS Code

Filtering decides which data answers your question, so it matters as much as the question itself. This chapter covers:

  • every place a filter can go: on a source, on a query, on a nest, on a single measure, and after aggregation

  • ordinary boolean filters: comparisons, and/or, alternation with |, the apply operator ?, and pattern matching

  • filter expressions: Malloy's compact mini-languages for filtering strings, numbers, dates, and booleans (the biggest section)

  • time comparisons: this year vs. last year, quarter over quarter, and how to handle partial periods

import "names.malloy"
import "ecommerce.malloy"

Part 1: Where filters go

Filtering a query

You know this one already. where: in a query keeps only matching rows before grouping:

run: names -> {
  where: state = 'WA' and year_born = 2021
  group_by: name
  aggregate: total_births
  limit: 5
}
QUERY RESULTS 
[
  {
    "name": "Olivia",
    "total_births": "452"
  },
  {
    "name": "Noah",
    "total_births": "408"
  },
  {
    "name": "Liam",
    "total_births": "402"
  },
  {
    "name": "Oliver",
    "total_births": "386"
  },
  {
    "name": "Henry",
    "total_births": "363"
  }
]
SELECT 
   base."name" as "name",
   COALESCE(SUM(base."number"),0) as "total_births"
FROM 'data/usa_names.parquet' as base
WHERE (base."state"='WA') and (base."year"=2021)
GROUP BY 1
ORDER BY 2 desc NULLS LAST
LIMIT 5

A comma between conditions means and. These two lines mean the same thing:

where: state = 'WA' and year_born = 2021
where: state = 'WA', year_born = 2021

Filtering a source

A where: inside extend { } builds the filter into the source itself, so every query against it is filtered. This is great for creating focused subsets:

source: modern_names is names extend {
  where: year_born >= 2000
}
run: modern_names -> {
  group_by: decade
  aggregate: total_births
}
QUERY RESULTS 
[
  {
    "decade": 2000,
    "total_births": "33079414"
  },
  {
    "decade": 2010,
    "total_births": "30624624"
  },
  {
    "decade": 2020,
    "total_births": "5594855"
  }
]
SELECT 
   (FLOOR(base."year"*1.0/10))*10 as "decade",
   COALESCE(SUM(base."number"),0) as "total_births"
FROM 'data/usa_names.parquet' as base
WHERE base."year">=2000
GROUP BY 1
ORDER BY 2 desc NULLS LAST

Filtering a single measure

You can attach a filter to one measure with { where: ... }. The rest of the query isn't affected. This is called a filtered aggregate, and it's the key to comparisons:

run: names -> {
  group_by: state
  aggregate:
    total_births
    girls is total_births { where: gender = 'F' }
    boys is total_births { where: gender = 'M' }
  limit: 5
}
QUERY RESULTS 
[
  {
    "state": "CA",
    "total_births": "32042437",
    "girls": "15340742",
    "boys": "16701695"
  },
  {
    "state": "NY",
    "total_births": "25168305",
    "girls": "12189627",
    "boys": "12978678"
  },
  {
    "state": "TX",
    "total_births": "24186112",
    "girls": "11632008",
    "boys": "12554104"
  },
  {
    "state": "PA",
    "total_births": "17533809",
    "girls": "8572244",
    "boys": "8961565"
  },
  {
    "state": "IL",
    "total_births": "16099446",
    "girls": "7767970",
    "boys": "8331476"
  }
]
SELECT 
   base."state" as "state",
   COALESCE(SUM(base."number"),0) as "total_births",
   (COALESCE(SUM(CASE WHEN base."gender"='F' THEN base."number" END),0)) as "girls",
   (COALESCE(SUM(CASE WHEN base."gender"='M' THEN base."number" END),0)) as "boys"
FROM 'data/usa_names.parquet' as base
GROUP BY 1
ORDER BY 2 desc NULLS LAST
LIMIT 5

One query, three different filters, three columns. In SQL you'd write SUM(CASE WHEN gender = 'F' THEN number END).

Filtering after aggregation: having

where: filters rows before grouping. To filter groups after aggregating ("only show names with more than 1 million births"), use having::

Part 2: Boolean filters

Comparison and logic

The usual operators work: =, !=, <, <=, >, >=, plus and, or, and not. Use parentheses to group:

run: names -> {
  where: (state = 'AK' or state = 'HI') and not (gender = 'M')
  group_by: state
  aggregate: total_births
}
QUERY RESULTS 
[
  {
    "state": "HI",
    "total_births": "452769"
  },
  {
    "state": "AK",
    "total_births": "194634"
  }
]
SELECT 
   base."state" as "state",
   COALESCE(SUM(base."number"),0) as "total_births"
FROM 'data/usa_names.parquet' as base
WHERE (((base."state"='AK') or (base."state"='HI'))) and COALESCE(NOT ((base."gender"='M')),TRUE)
GROUP BY 1
ORDER BY 2 desc NULLS LAST

Alternation with |

Writing state = 'AK' or state = 'HI' or state = 'PR' is tedious. Malloy lets you write state = 'AK' | 'HI' | 'PR'. Use != to exclude a list:

run: names -> {
  where: state != 'CA' | 'TX' | 'NY', year_born = 2021
  group_by: state
  aggregate: total_births
  limit: 5
}
QUERY RESULTS 
[
  {
    "state": "FL",
    "total_births": "175115"
  },
  {
    "state": "PA",
    "total_births": "103541"
  },
  {
    "state": "OH",
    "total_births": "101860"
  },
  {
    "state": "IL",
    "total_births": "101795"
  },
  {
    "state": "NC",
    "total_births": "95220"
  }
]
SELECT 
   base."state" as "state",
   COALESCE(SUM(base."number"),0) as "total_births"
FROM 'data/usa_names.parquet' as base
WHERE (base."state" NOT IN ('CA','TX','NY'))
AND (base."year"=2021)
GROUP BY 1
ORDER BY 2 desc NULLS LAST
LIMIT 5

The apply operator ?

? applies a partial comparison to a value. It reads nicely for ranges and sets of conditions:

Expression Means
year_born ? > 1990 & < 2000 year_born > 1990 and year_born < 2000
year_born ? 1990 to 2000 year_born >= 1990 and year_born < 2000 (the end is excluded)
state ? 'UT' | 'ID' state = 'UT' or state = 'ID' 
run: names -> {
  where: year_born ? 1946 to 1965, name ? 'Linda' | 'Mary' | 'Patricia'
  group_by: name
  aggregate: total_births
}
QUERY RESULTS 
[
  {
    "name": "Mary",
    "total_births": "1127394"
  },
  {
    "name": "Linda",
    "total_births": "1061014"
  },
  {
    "name": "Patricia",
    "total_births": "789525"
  }
]
SELECT 
   base."name" as "name",
   COALESCE(SUM(base."number"),0) as "total_births"
FROM 'data/usa_names.parquet' as base
WHERE ((base."year">=1946) and (base."year"<1965))
AND (base."name" IN ('Linda','Mary','Patricia'))
GROUP BY 1
ORDER BY 2 desc NULLS LAST

Pattern matching with ~

~ matches a string against a pattern. With a normal string, it works like SQL LIKE: % matches any run of characters and _ matches exactly one. With an r'...' string, it's a regular expression. !~ means "does not match."

run: names -> {
  where: year_born = 2021, name ~ r'^(Ja|Jo)[a-z]*n$'
  group_by: name
  aggregate: total_births
  limit: 8
}
QUERY RESULTS

    "name": "Jackson",
    "total_births": "9197"
  },
  {
    "name": "John",
    "total_births": "8130"
  },
  {
    "name": "Jayden",
    "total_births": "6974"
  },
  {
    "name": "Jaxon",
    "total_births": "5693"
  },
  {
    "name": "Jordan",
    "total_births": "4680"
  },
  {
    "name": "Jonathan",
    "total_births": "4405"
  },
  {
    "name": "Jameson",
    "total_births": "4286"
  },
  {
    "name": "Jaxson",
    "total_births": "3673"
  }
]
SELECT 
   base."name" as "name",
   COALESCE(SUM(base."number"),0) as "total_births"
FROM 'data/usa_names.parquet' as base
WHERE (base."year"=2021)
AND (REGEXP_MATCHES(base."name",'^(Ja|Jo)[a-z]*n$'))

That regular expression means "starts with Ja or Jo, then any lowercase letters, then ends with n."

Nulls

Use is null and is not null. (A plain = null never matches anything, just like in SQL.)

run: order_items -> {
  aggregate:
    items is order_item_count
    returned is order_item_count { where: returned_at is not null }
    never_shipped is order_item_count { where: shipped_at is null }
}
QUERY RESULTS 
[
  {
    "items": 271019,
    "returned": 2672,
    "never_shipped": 10737
  }
]
SELECT 
   (COUNT(1)) as "items",
   (COUNT(CASE WHEN base."returned_at" IS NOT NULL THEN 1 END)) as "returned",
   (COUNT(CASE WHEN base."shipped_at" IS NULL THEN 1 END)) as "never_shipped"
FROM 'data/order_items.parquet' as base

Part 3: Filter expressions

Here is the most powerful filtering tool in Malloy. A filter expression is a small string written in a special mini-language, then applied with ~. It starts with f and is wrapped in quotes: f'...'.

name ~ f'Ja%, -Jason'        // starts with "Ja", but isn't "Jason"
year_born ~ f'[1990 to 2000)'  // 1990 through 1999
created_at ~ f'2021-Q4'      // any time in the 4th quarter of 2021

Why have a separate language? Because filters are data. A dashboard's filter box, a URL parameter, a given, or an LLM can produce a short string like CA, NY, -TX or last 3 months, and Malloy turns it into correct SQL for whatever database you use. There's a mini-language for each type: strings, numbers, temporal (dates and timestamps), and booleans.

📘 Malloy docs. Filter expressions. Keep this page handy. It has the full grammar.

String filter expressions

Filter expression Matches
f'Emma' exactly Emma
f'Emma, Olivia, Ava' any of the three
f'Em%' starts with Em
f'%lyn' ends with lyn
f'%ann%' contains ann
f'J_n' J, any one character, n (Jan, Jen, Jon...)
f'-Emma' anything except Emma
f'null' / f'-null' is / isn't null
f'empty' null or the empty string

QUERY RESULTS

That's "(starts with A or starts with E) and ends with a".

To exclude several patterns, put a - in front of each one. Or wrap the whole match in not ( ). These two filters mean the same thing: "states that don't start with C, N, or T":

where: state ~ f'-C%, -N%, -T%'
where: not (state ~ f'C%, N%, T%')
run: names -> {
  where: year_born = 2021, state ~ f'-C%, -N%, -T%'
  group_by: state
  aggregate: total_births

}
QUERY RESULTS

⚠️ Avoid !~ with filter expressions. You might expect state !~ f'C%, N%, T%' to work too. In the Malloy version used to build this book, it silently ignores the ! and returns the matching rows. Always check results when you negate a filter. Use - inside the expression or not (...) around it instead.

💡 Escaping. To match a real %, _, ,, or a leading -, put a backslash before it: f'100%'.

Numeric filter expressions

Filter expression Matches
f'42' or f'= 42' equals 42
f'2, 4, 6' any of these
f'> 1000' more than 1000 (also <, <=, >=, !=)
f'[1990 to 1999]' 1990 through 1999: square brackets include the ends
f'(1990 to 2000)' between 1990 and 2000: parentheses exclude the ends (1991–1999)
f'[1990 to 2000)' mix them: includes 1990, excludes 2000
f'> 10 and < 20' combine with and / or
f'not [1 to 9]' outside the range
f'null' is null

This is the same interval notation used in math class: [ and ] mean "including," and ( and ) mean "not including."

⚠️ Check the brackets. At the time of writing, the filter expression page in the Malloy documentation describes ( ) and [ ] the other way around. The behavior shown here was checked against the SQL that Malloy actually generates ([1946 to 1964] becomes year >= 1946 AND year <= 1964). When in doubt, click the SQL button and read the WHERE clause.

Temporal filter expressions

Temporal (date and timestamp) filter expressions are where this language really shines. They know about calendars. Let's switch to the e-commerce data, which has real timestamps.

Literals: a moment that implies a duration

Filter expression Matches
f'2021' all of 2021
f'2021-Q4' Oct 1 – Dec 31, 2021
f'2021-03' March 2021
f'2021-03-14' that day
f'2021-03-14-WK' the week starting that day
f'2021-03-14 10' the 10 o'clock hour 
run: order_items -> {
  aggregate:
    all_time is total_sales
    in_2021 is total_sales { where: created_at ~ f'2021' }
    in_2021_q4 is total_sales { where: created_at ~ f'2021-Q4' }
    in_dec_2021 is total_sales { where: created_at ~ f'2021-12' }
    on_xmas_eve is total_sales { where: created_at ~ f'2021-12-24' }
}
QUERY RESULTS 
[
  {
    "all_time": 12566292.875474572,
    "in_2021": 3900910.8143820763,
    "in_2021_q4": 1112858.0839500427,
    "in_dec_2021": 420505.65155911446,
    "on_xmas_eve": 13777.830094099045
  }
]
SELECT 
   (COALESCE(SUM(base."sale_price"),0)) as "all_time",
   (COALESCE(SUM(CASE WHEN base."created_at" >= TIMESTAMP '2021-01-01 00:00:00' AND base."created_at" < TIMESTAMP '2022-01-01 00:00:00' THEN base."sale_price" END),0)) as "in_2021",
   (COALESCE(SUM(CASE WHEN base."created_at" >= TIMESTAMP '2021-09-01 00:00:00' AND base."created_at" < TIMESTAMP '2021-12-01 00:00:00' THEN base."sale_price" END),0)) as "in_2021_q4",
   (COALESCE(SUM(CASE WHEN base."created_at" >= TIMESTAMP '2021-12-01 00:00:00' AND base."created_at" < TIMESTAMP '2022-01-01 00:00:00' THEN base."sale_price" END),0)) as "in_dec_2021",

Relative times

Filter expressions also understand relative time:

Filter expression Matches
f'today', f'yesterday' that day
f'this month', f'last quarter', f'next year' the current/previous/next period
f'last 7 days' the 7 complete days before today
f'2 weeks ago' the week two weeks back
f'last monday' the most recent Monday
f'2 years ago to now' combine with to

These are measured from right now, the moment the query runs. Our e-commerce data ends in November 2022, so watch what happens:

run: order_items -> {
  aggregate:
    last_30_days is order_item_count { where: created_at ~ f'last 30 days' }
    this_year is order_item_count { where: created_at ~ f'this year' }
    last_5_years is order_item_count { where: created_at ~ f'last 5 years' }
}
QUERY RESULTS 
[
  {
    "last_30_days": 0,
    "this_year": 0,
    "last_5_years": 186423
  }
]
SELECT 
   (COUNT(CASE WHEN base."created_at" >= (DATE_TRUNC('day', LOCALTIMESTAMP) - INTERVAL (30) day) AND base."created_at" < DATE_TRUNC('day', LOCALTIMESTAMP) THEN 1 END)) as "last_30_days",
   (COUNT(CASE WHEN base."created_at" >= DATE_TRUNC('year', LOCALTIMESTAMP) AND base."created_at" < (DATE_TRUNC('year', LOCALTIMESTAMP) + INTERVAL (1) year) THEN 1 END)) as "this_year",
   (COUNT(CASE WHEN base."created_at" >= (DATE_TRUNC('year', LOCALTIMESTAMP) - INTERVAL (5) year) AND base."created_at" < DATE_TRUNC('year', LOCALTIMESTAMP) THEN 1 END)) as "last_5_years"
FROM 'data/order_items.parquet' as base

Zeros are the correct answer for the first two, because there were no orders in the last 30 days! Relative filters are perfect for live production data ("sales this month"), and confusing for historical datasets. With historical data, use literal dates.

⚠️ Relative filters depend on when you run them. The numbers in this cell will be different next year. That's good for a live dashboard, but bad for a homework answer you want to reproduce!

Combining temporal filters uses and, or, and parentheses. Here's "Q4 of 2020 or Q4 of 2021":

Filter expression true false null
f'true' ✅
f'false' ✅ ✅ (treats null as false)
f'=false' ✅

(The extend: inside a query adds a field just for that query. More on that in Chapter 12.)

Filter expressions vs. ordinary expressions

Both work, and you can mix them. Here are the same filters written both ways:

Ordinary Malloy Filter expression
state = 'CA' | 'NY' state ~ f'CA, NY'
name ~ 'Ja%' and name != 'Jason' name ~ f'Ja%, -Jason'
year_born >= 1990 and year_born <= 1999 year_born ~ f'[1990 to 1999]'
created_at ? @2021-10 to @2022-01 created_at ~ f'2021-Q4'

Use whichever reads more clearly. Filter expressions win when the filter is long, involves calendars, or comes from outside your code (a user, a parameter, or an app).

Watch out for partial periods

What about 2022 vs. 2021? Our data stops on November 14, 2022. Comparing "all of 2022" with "all of 2021" compares 10½ months with 12 months, which isn't fair. The fix is to compare the same slice of the calendar, year-to-date:

run: order_items -> {
  aggregate:
    full_2021 is total_sales { where: created_at ~ f'2021' }
    partial_2022 is total_sales { where: created_at ~ f'2022' }

    ytd_2022 is total_sales { where: created_at ~ f'2022-01-01 to 2022-11-15' }
    # percent
    ytd_growth is total_sales { where: created_at ~ f'2022-01-01 to 2022-11-15' }
      / total_sales { where: created_at ~ f'2021-01-01 to 2021-11-15' } - 1

Baby names: then vs. now

Filtered measures make period comparisons easy on the names data, too. Which names grew the most from the 1990s to the 2010s?

run: names -> {
  where: gender = 'F'
  group_by: name
  aggregate:
    births_1990s is total_births { where: decade = 1990 }
    births_2010s is total_births { where: decade = 2010 }
    # number="0.00"
    growth_factor is total_births { where: decade = 2010 }
      / nullif(total_births { where: decade = 1990 }, 0)
  having: total_births { where: decade = 2010 } > 50000
  order_by: growth_factor desc
  limit: 10
}

SELECT 
   base."name" as "name",
   (COALESCE(SUM(CASE WHEN ((FLOOR(base."year"*1.0/10))*10)=1990 THEN base."number" END),0)) as "births_1990s",
   (COALESCE(SUM(CASE WHEN ((FLOOR(base."year"*1.0/10))*10)=2010 THEN base."number" END),0)) as "births_2010s",
   ((COALESCE(SUM(CASE WHEN ((FLOOR(base."year"*1.0/10))*10)=2010 THEN base."number" END),0)))*1.0/(NULLIF((COALESCE(SUM(CASE WHEN ((FLOOR(base."year"*1.0/10))*10)=1990 THEN base."number" END),0)),0)) as "growth_factor"
FROM 'data/usa_names.parquet' as base
WHERE base."gender"='F'
GROUP BY 1
HAVING ((COALESCE(SUM(CASE WHEN ((FLOOR(base."year"*1.0/10))*10)=2010 THEN base."number" END),0)))>50000
ORDER BY 4 desc NULLS LAST
LIMIT 10

Key takeaways

  • Filters can go on a source (extend { where: }), a query (where:), a nest, a single measure (measure { where: }), or after aggregation (having:).

  • | lists alternatives, ? applies partial comparisons and ranges, and ~ matches patterns.

  • Filter expressions (f'...') are compact mini-languages for strings, numbers, times, and booleans:

    • strings: lists, % wildcards, - to exclude

    • numbers: comparisons and (a to b) / [a to b] ranges

    • times: 2021-Q4, 2021-01 to 2021-04, before 2020, last 3 months, ...

  • Relative time filters (last 30 days) depend on when you run the query.

  • Period-over-period analysis is a set of filtered measures compared side by side. Compare like with like when a period is partial.
