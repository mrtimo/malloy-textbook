Chapter 13: Pipelines, Step by Step

Open in VS Code

Chapter 12 introduced pipelines quickly, alongside window functions. This chapter slows down. Every example is shown in two steps: first a normal query and its result, then the same query with a pipeline added, and the new result. Watch how the second result is built from the first.

The big idea

Every query you've written so far produces a table: the result. A pipeline runs a second query on that result table.

You've done this in a spreadsheet. You make a pivot table (births by name), and then you work with the pivot table itself: count its rows, filter it, sort it, or make a second pivot table from it.

In Malloy, the arrow -> means "and then":

run: names -> { first query } -> { second query }
  names data          stage 1                 stage 2
 (millions of   ->   result table    ->      final result
    rows)           (one row per name)      (one row)

Two rules make pipelines easy:

  1. Stage 2 only sees stage 1's result. It can use the columns stage 1 produced, and nothing else.

  2. Build one stage at a time. Run stage 1, look at the result, then add -> and stage 2.

import "names.malloy"
import "ecommerce.malloy"

Step 2. Add -> and a second stage that works on that table:

run: names -> {
  where: year_born = 2021 and gender = 'F'
  group_by: name
  aggregate: total_births
} -> {
  where: total_births > 1000
  aggregate: popular_names is count()
}
QUERY RESULTS
🔗 Link 
[
  {
    "popular_names": 314
  }
]
WITH __stage0 AS (
  SELECT 
     base."name" as "name",
     COALESCE(SUM(base."number"),0) as "total_births"
  FROM 'data/usa_names.parquet' as base
  WHERE (base."year"=2021) and (base."gender"='F')
  GROUP BY 1
)
SELECT 
   COUNT(1) as "popular_names"
FROM __stage0 as base
WHERE base."total_births">1000

314 names. Read it in plain English:

  • Stage 1: make a table with one row per girls' name in 2021, and its births.

  • Stage 2: keep the rows of that table with more than 1,000 births, and count them.

In stage 2, total_births is just a column of the table, like a column in a spreadsheet. count() counts names now, because each row of stage 1's table is one name.

💡 Why not use having:? having: total_births > 1000 in stage 1 would filter the names. But it would still give you a list of 314 names, not the number 314. To count the rows of a result, you need a second stage.

The average state had about 55,000 babies in this data, but the range is huge: 2,142 in the smallest and 359,997 in the biggest (California).

Why do you need a pipeline? avg(births) in one query would average the raw rows (one row per name, state and year), which answers a different question: "how many babies does a typical name get in a typical state?" You want the average of the state totals, so you first make the totals (stage 1), then average them (stage 2).

WITH __stage0 AS (
  SELECT 
     base."user_id" as "user_id",
     count(distinct base."order_id") as "order_count"
  FROM 'data/order_items.parquet' as base
  GROUP BY 1
)
, __stage1 AS (
  SELECT
    group_set,
    CASE WHEN group_set=1 THEN
      base."order_count"
      END as "order_count__1",
    CASE WHEN group_set=1 THEN
      COUNT(1)
      END as "customers__1",
    CASE WHEN group_set=1 THEN
      COUNT(1)
      END*1.0/MAX(CASE WHEN group_set=0 THEN
      COUNT(1)
      END) OVER () as "share_of_customers__1"
  FROM __stage0 as base
  CROSS JOIN (SELECT UNNEST(GENERATE_SERIES(0,1,1)) as group_set  ) as group_set
  GROUP BY 1,2
)
SELECT
  "order_count__1" as "order_count",
  MAX(CASE WHEN group_set=1 THEN "customers__1" END) as "customers",
  MAX(CASE WHEN group_set=1 THEN "share_of_customers__1" END) as "share_of_customers"
FROM __stage1
WHERE group_set NOT IN (0)
GROUP BY 1
ORDER BY 1 ASC NULLS LAST

51% of customers ordered only once, 24% twice, and 12% three times. Just 4 customers ordered 15 times.

Notice that order_count was a measure in stage 1, but in stage 2 it's a column you can group by. That's the most common reason to use a pipeline: you want to group by something you calculated.

Example 4: grouping a calculated number into buckets

Question: How many girls' names in 2021 were very popular, popular, uncommon or rare?

Stage 1 is the same as Example 1. Stage 2 uses pick (from Chapter 9) to sort each name into a size group, then counts:

run: names -> {
  where: year_born = 2021 and gender = 'F'
  group_by: name
  aggregate: total_births
} -> {
  group_by: size_group is total_births ?
    pick '1. Over 10,000' when >= 10000
    pick '2. 1,000 to 9,999' when >= 1000
    pick '3. 100 to 999' when >= 100
    else '4. Under 100'
  aggregate:
    names is count()
    babies is total_births.sum()
  order_by: size_group
}
QUERY RESULTS

  {

    "names": 8,
    "babies": "106950"
  },
  {
    "size_group": "2. 1,000 to 9,999",
    "names": 306,
    "babies": "743820"
  },
  {
    "size_group": "3. 100 to 999",
    "names": 1119,
    "babies": "378240"
  },
  {
    "size_group": "4. Under 100",
    "names": 3889,
    "babies": "91085"
  }

WITH __stage0 AS (
  SELECT 
     base."name" as "name",
     COALESCE(SUM(base."number"),0) as "total_births"
  FROM 'data/usa_names.parquet' as base
  WHERE (base."year"=2021) and (base."gender"='F')
  GROUP BY 1
)
SELECT 
   CASE WHEN (base."total_births">=10000) THEN '1. Over 10,000' WHEN (base."total_births">=1000) THEN '2. 1,000 to 9,999' WHEN (base."total_births">=100) THEN '3. 100 to 999' ELSE '4. Under 100' END as "size_group",
   COUNT(1) as "names",
   COALESCE(SUM(base."total_births"),0) as "babies"
FROM __stage0 as base
GROUP BY 1
ORDER BY 1 ASC NULLS LAST

Only 8 names were given to more than 10,000 girls, but together they covered about 107,000 babies. Meanwhile 3,889 names (73% of all names) were rare, with fewer than 100 babies each.

In stage 2, names is count() counts names (rows of stage 1), and total_births.sum() adds up the babies.

Example 5: filtering on a rank

Question: Which name was the #1 boys' name each year?

Step 1. Rank the names within each year with calculate: (Chapter 12):

run: names -> {
  where: gender = 'M' and year_born >= 2019
  group_by: year_born, name
  aggregate: total_births
  calculate: rank_in_year is rank() { partition_by: year_born  order_by: total_births desc }
  order_by: year_born desc, total_births desc
  limit: 6
}

Putting it together: a question in two stages

Question: In 2021, which girls' names were #1 in the most states?

Say the two stages out loud first:

  • Stage 1: for each state, rank the girls' names.

  • Stage 2: keep each state's #1 name, then count states per name.

run: names -> {
  where: year_born = 2021 and gender = 'F'
  group_by: state, name
  aggregate: total_births
  calculate: rank_in_state is rank() { partition_by: state  order_by: total_births desc }
} -> {
  where: rank_in_state = 1
  group_by: name
  aggregate: states_where_number_1 is count()
  order_by: states_where_number_1 desc
}

A common mistake: using a column stage 1 didn't make

Stage 2 can only use the columns in stage 1's result. This fails:

run: names -> {
  where: year_born = 2021
  group_by: state
  aggregate: total_births
} -> {
  group_by: gender
  aggregate: n is count()
}
'gender' is not defined

Stage 1's table has only two columns, state and total_births. gender was in the raw data, but it didn't make it into the result. To use it in stage 2, add it to stage 1's group_by:.

💡 When you get stuck, delete everything after the -> and run stage 1 alone. Look at its columns. Those are the only names stage 2 can use.

When do you need a pipeline?

Use a pipeline when your question has the words "of the" or "each … then" in it:

Question Stage 1 Stage 2
How many names had over 1,000 births? births per name count the rows that pass a filter
What's the average of the state totals? total per state average the totals
How many customers ordered once, twice…? orders per customer group by the order count
Which was the #1 name each year? rank names in each year keep rank 1

If you can answer in one query, do. A pipeline is for when the first answer is a table you need to work on again.

Key takeaways

  • A pipeline runs a query on the result of another query. -> means "and then."

  • Stage 2 sees only stage 1's columns. A measure in stage 1 (like total_births) becomes a plain column in stage 2 that you can filter, group by, average or count.

  • In stage 2, count() counts rows of stage 1's result, such as names, states or customers.

  • Common reasons for a second stage: counting the rows of a result, averaging totals, grouping by a calculated number, and filtering on a rank.

  • Build one stage at a time. Run stage 1, look at the result, then add the next stage.
